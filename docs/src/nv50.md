# NVIDIA nv50

Tunix drives NVIDIA's nv50 family (Tesla) itself: the display from the first
line of the console on, and, on the GT21x chips, the GPU for Mesa's `nouveau`
gallium driver, which runs OpenGL and OpenGL ES on it unchanged.

## When it takes the card

The driver is a module, `nv50.ko`, that comes in the
[initramfs](boot.md#the-initramfs): the kernel loads it when the machine has an
NVIDIA display controller, before it draws the console, so the driver takes the
screen from the first line on. Loaded any later, by udev, it declines, having
come too late to. Once loaded, it takes the card by itself, as Linux's nouveau
does, when

- the card is a GT215, GT216 or GT218 (chipsets `a3`, `a5`, `a8`), the chips it
  has been verified on, and
- the screen the firmware left behind is on this card: its framebuffer lies in
  the card's VRAM window. On a laptop whose panel another GPU drives, the NVIDIA
  card is left alone.

| Parameter | Effect |
| --- | --- |
| `nonv50`, `nomodeset` | leave the firmware framebuffer as it is; the module does not load |
| `modprobe.blacklist=nv50` | the same, by keeping the module from loading |
| `nv50` | drive any nv50-family chip, verified or not, even off the boot screen |
| `nv50fifo` | run the FIFO, copy engine and PGRAPH self-tests at boot |
| `drmtrace` | log DRM ioctls: the first 400 of each process, and every one that fails or takes over 5 ms |

## The pieces

| File | What it is |
| --- | --- |
| `drivers/gpu/nv50/bios.c`, `dcb.c`, `init.c` | The video BIOS: its output table and the init scripts that power the panel |
| `drivers/gpu/nv50/disp.c`, `i2c.c` | The display engine: modes, EDID, cursor, gamma, vblank |
| `drivers/gpu/nv50/fifo.c` | VRAM, the GPU's page tables, PFIFO channels, the copy engine |
| `drivers/gpu/nv50/gr.c`, `ctxnv50.c` | PGRAPH, with nouveau's context program, and the 2D engine |
| `drivers/gpu/nv50/nouveau.c` | nouveau's DRM interface (1.3.1): clients, channels, buffers, submissions |
| `drivers/gpu/nv50/nv50.c` | Binding, page flipping, and what DRM's presents go through |

## Buffers on the screen

A client's buffer in VRAM is shown by copying it into the scanout on the GPU:
the copy engine takes linear buffers, the 2D engine tiled ones, which it reads
through a mapping with the buffer's kind. Tiled buffers keep whole VRAM row
blocks to themselves (`nv50_fb_vram_rblock`), as the memory controller's
partition swizzle requires.
